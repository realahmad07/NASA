# Scientific Evidence and Provenance Policy

PyroSage is an evidence-analysis interface for microgravity combustion research. Its outputs must preserve the distinction between source observations, computed measurements, model interpretation, and future research hypotheses.

## Evidence classes
| Class | Meaning | Required presentation |
|---|---|---|
| Source record | Metadata or asset retrieved from NASA PSI | PSI accession and source URL |
| Uploaded evidence | File selected by the operator | Original filename and file metadata |
| Computed descriptor | Value calculated by a local algorithm | Method, units, frame/time range, and parameters |
| Model interpretation | Text generated by the selected LLM | Provider/model and evidence references |
| Candidate match | Similarity result against an indexed PSI record | Candidate accession and match features |
| Hypothesis | Proposed explanation or future test | Explicitly label as a hypothesis |

## Technique execution states
- **Executed:** Required modality and implementation were available and a result was calculated.
- **Partially executed:** A limited subset ran; disclose missing dimensions.
- **Requires data:** Required measurement or modality was not present.
- **Requires specialist solver:** The method needs a dedicated solver, calibration, trained weights, or validated scientific implementation.
- **Not applicable:** The method does not apply to the selected evidence.

A technique name in the registry is not proof that the technique ran.

## NASA PSI provenance
- NASA PSI is the authoritative source for repository-backed experiment records in the NASA-only workflow.
- Preserve accession identifiers, investigation titles, source URLs, and retrieved timestamps when available.
- Only assets linked from a verified PSI investigation may enter the PSI evidence pipeline.
- Similarity matching must return actual catalogue record IDs; never generate accession identifiers.
- User-uploaded files must not be relabelled as NASA data unless their provenance is verified.
- Do not merge unrelated public datasets into the NASA-only experiment catalogue.

## LLM operating boundary
- Pass only selected technique IDs and their descriptions/prerequisites.
- Pass only uploaded evidence descriptors and verified PSI candidate records.
- Require structured outputs with evidence references.
- Reject or flag experiment IDs not present in the candidate set.
- Treat unsupported measurements as unavailable, not zero.
- Do not allow the model to claim a specialist solver ran unless the backend supplies a corresponding execution result.

## Reporting language
Prefer statements such as:
- “The uploaded frame has a computed bilateral symmetry score of …”
- “The PSI catalogue returned these candidate investigations …”
- “The model interprets the measured trend as …”
- “The current evidence does not contain calibrated temperature data.”

Avoid claiming NASA proved a result when the source record does not say so, claiming PIV ran without valid particle imagery and a solver, reporting temperature from uncalibrated RGB imagery, or calling an unvalidated gravity interpolation a lunar-fire prediction.
